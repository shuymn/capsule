# Architecture

Read this file when changing session ownership, acquisition, rendering, or shell integration. Read [threat-model.md](threat-model.md) before changing trust boundaries, execution authority, or distribution. Keep zsh input responsive on macOS and Linux and minimize the code one maintainer must own. Support the two-line prompt, directory, Git, status/vi mode, duration, optional time, configured values, styles, and reload.

## Ownership

Run one worker per interactive zsh session on Tokio's current-thread runtime. The public CLI is `init zsh` and `preset`; `worker` and `fd-config` are internal commands.

| Owner | Responsibility |
| --- | --- |
| [init.zsh](../crates/core/src/init/init.zsh) | Shell generation, full exported snapshot, nonblocking pipe buffers, fallback, zle hooks |
| [worker/machine.rs](../crates/cli/src/worker/machine.rs) | Sans-IO state machine: one active acquisition generation, newest pending replacement, reload acceptance, fresh observations, settled display snapshot |
| [worker.rs](../crates/cli/src/worker.rs) | I/O shell: pipes, signals, generation tasks, acquisition, response writer |
| [plan.rs](../crates/core/src/plan.rs) | Immutable schema-v2 ConfigPlan: validated sources, conditions, indexed formats, display settings |
| [acquire.rs](../crates/core/src/acquire.rs), [plan/acquire.rs](../crates/core/src/plan/acquire.rs), [git.rs](../crates/core/src/git.rs) | Bounded env/file/argv acquisition, sequential fallback, Git CLI and directory facts |
| [view.rs](../crates/core/src/view.rs), [render/style.rs](../crates/core/src/render/style.rs) | Pure evaluation, arbitration, structured text/style, grapheme layout, final zsh serialization and prompt-escape quoting |
| [session.rs](../crates/protocol/src/session.rs) | Authoritative byte-frame grammar and persistent cancellation-safe framing |

Use generic configuration for tool-specific values; see [extending.md](extending.md). Presets embed [examples/config.toml](../examples/config.toml). Keep acquisition I/O outside View.

## Behavioral contract

Each clause's `Spec:` lists the tests that specify it; change them together.

- WHILE acquisition is pending, Capsule SHALL accept input and preserve the typed buffer/cursor during redraw. Spec: `asynchronous_prompt_update_preserves_typed_buffer_and_cursor`.
- WHEN zsh prepares a prompt, including after empty Enter, Capsule SHALL start a generation and reload configuration asynchronously, capturing cwd and the full exported environment as OS bytes after preserved `precmd_functions` hooks complete or abort. Spec: `user_hooks_finish_before_snapshot_and_first_revalidation_retains_display`, `user_hook_changes_keep_snapshot_shell_status_and_literal_prompt_for_commands_and_empty_enter`, `full_export_snapshot_preserves_bytes_and_removes_absent_variables`, `cwd_bytes_reach_acquisition`, `repeated_empty_enter_settles_on_the_newest_generation_with_one_worker`, `directory_hook_exports_reach_the_directory_change_generation`.
- WHILE revalidating an identical cwd/environment snapshot, Capsule SHALL retain the last settled external display, including directory metadata, Git, and custom modules; new partial results SHALL remain hidden. Spec: `machine_follows_the_reference_model`, `partial_results_stay_hidden`, `same_snapshot_retains_all_pending_frames_and_commits_external_changes_together`, `ordinary_command_preserves_git_and_tools_in_every_render_and_precmd`.
- WHEN cwd or any exported variable's presence or bytes change, Capsule SHALL discard retained external display immediately. Environment ordering SHALL NOT affect snapshot identity. Spec: `changed_snapshot_discards_retained_display`, `snapshots_round_trip_independent_of_environment_order`, `changed_environment_cwd_and_valid_config_clear_retained_information`, `changed_cwd_discards_settled_external_display_immediately`, `changed_exported_environment_discards_settled_external_display_immediately`.
- WHEN reload accepts different configuration source text (including removal), Capsule SHALL discard retained display before using the new plan. Until reload settles, same-input retention SHALL be provisional; a rejected configuration SHALL retain the last valid plan. Spec: `accepted_plan_change_discards_retained_display`, `removing_the_configuration_accepts_the_defaults`, `cancellation_and_failed_reload_retain_the_last_settled_generation`, `changed_valid_config_clears_display_after_plan_load_before_acquisition_finishes`, `invalid_config_retains_previous_valid_plan_and_settled_display`.
- WHEN a generation settles, including failure or timeout, Capsule SHALL atomically replace the external display with that generation's observations, removing results whose conditions are false or whose required values are Missing or Failed. Spec: `machine_follows_the_reference_model`, `events_queued_before_a_failed_task_cannot_change_its_settled_display`, `external_snapshot_commits_atomically_and_clears_missing_values_and_false_conditions`, `failed_value_is_retained_pending_then_cleared_when_settled`.
- WHEN exit status, duration, width, or keymap changes, Capsule SHALL render these local inputs without waiting for external acquisition. Width and keymap SHALL NOT trigger reacquisition. Spec: `local_inputs_rerender_without_reacquisition`, `width_and_keymap_redraw_reuse_the_same_observations`, `pending_acquisition_renders_status_duration_resize_and_vi_without_losing_input`.
- WHEN zsh prepares a prompt, Capsule SHALL use zsh's `$?` as seen by the first Capsule hook as the exit status, and SHALL provide a duration only for a command that started since the previous prompt, including after a prompt that skipped Capsule's hooks and for commands that run a nested line editor such as `vared`. Spec: `prompt_without_command_reports_shell_status_and_no_duration`, `empty_enter_after_named_precmd_error_omits_stale_duration`, `named_precmd_recovery_keeps_command_status_and_worker`, `command_using_nested_line_editor_keeps_its_duration`.
- WHEN transport fails or the worker stops, Capsule SHALL select fallback and discard worker-owned retained display; the next prompt SHALL start a replacement worker. Spec: `failed_redraw_write_selects_fallback_after_transport_cleanup`, `worker_failure_uses_fallback_and_next_command_restarts_worker`, `hook_errors_do_not_prevent_snapshot_invalidation_or_replacement_worker_startup`.
- WHEN spawning a command, Capsule SHALL use direct argv and replace its environment with the snapshot, preserving absent versus empty variables and non-UTF-8 bytes. Non-exported parameters, aliases, and functions are excluded. Spec: `command_uses_direct_argv_and_replaces_the_environment`, `full_export_snapshot_preserves_bytes_and_removes_absent_variables`.
- WHEN one generation requests the same argv with the same cwd and environment more than once, Capsule SHALL run it once and share its outcome, including failure; a later generation SHALL run it again. Spec: `deduplicating_runner_shares_failures`, `identical_commands_run_once_per_generation_across_values_and_modules`.
- WHEN a snapshot exceeds its bound, Capsule SHALL omit acquisition rather than truncate the snapshot. Diagnostics SHALL exclude environment contents. Spec: `oversized_snapshot_omits_the_request_and_selects_fallback`, `oversized_snapshot_is_rejected_without_running_a_command`, `rejected_frames_do_not_expose_environment_values`.
- WHEN configuration validation fails, Capsule SHALL reject the entire new plan, report the reason, and retain the last valid plan; a fresh worker uses defaults. Spec: `failed_reload_preserves_last_valid_plan_then_accepts_fixed_configuration`, `a_fresh_worker_with_an_invalid_configuration_renders_defaults`, `invalid_configuration_keeps_the_previous_plan_and_reports_the_reason`, `source_and_regex_validation_happens_before_acquisition`.
- WHEN evaluating a display snapshot, Capsule SHALL hide a module whose condition is pending, false, or failed. WHEN a required value is unavailable, Capsule SHALL hide the module; unavailable optional sections SHALL be omitted. Spec: `format_evaluation_matches_the_reference_rule`, `arbitration_selects_the_lowest_priority_per_group`.
- WHEN a candidate is missing, fails extraction, fails execution, or times out, Capsule SHALL try the next candidate. WHEN a candidate is ready, including an empty value, Capsule SHALL stop fallback. Generation cancellation SHALL end acquisition. Spec: `missing_failed_and_timed_out_candidates_fall_back_in_order`, `regex_extraction_distinguishes_empty_capture_from_missing_capture`, `ready_empty_env_stops_fallback_but_unset_env_does_not`, `cancellation_does_not_fall_back_to_a_ready_value`, `cancellation_stops_running_commands_and_prevents_queued_spawns`.
- WHEN observations arrive in any order, Capsule SHALL retain declaration order and select at most one ready module per arbitration group across both slots, using lowest priority then declaration order. Spec: `machine_follows_the_reference_model`, `arbitration_selects_the_lowest_priority_per_group`, `arbitration_without_ties_ignores_declaration_order`, `custom_modules_render_on_their_slot_in_declaration_order_between_builtins`.
- WHEN rendering data, Capsule SHALL display controls as data, keep text/style separate through grapheme-safe width adjustment, and serialize styles and zsh prompt escapes last. Serialized data SHALL display literally whether zsh expands it with `PROMPT_SUBST` on or off: a named `precmd` function runs before Capsule's hooks and can change the option, then fail and skip them. Spec: `controls_are_display_data_before_width_calculation`, `truncation_fits_and_keeps_a_grapheme_prefix`, `rendered_lines_fit_the_columns_and_the_response_frame`, `literal_data_is_safe_with_prompt_substitution_on_and_off`, `named_precmd_error_expands_worker_display_literally`.
- WHEN preserved `precmd_functions` hooks complete or abort, Capsule SHALL finalize its retained prompt literally for the actual `PROMPT_SUBST` option, even without a new response. It SHALL run preserved hooks in order with the original command exit status, skip later user hooks only after a genuine shell error, forward `add-zsh-hook` across repeated initialization, preserve the user's option, and leave user-owned prompts unchanged; matching responses SHALL still replace Capsule's fallback. Spec: `retained_prompt_tracks_user_hook_option_changes_before_a_response`, `preserved_hooks_keep_options_order_and_continue_after_nonzero_returns`, `generated_init_preserves_user_hooks_and_can_be_evaluated_twice`, `user_owned_prompt_survives_snapshot_invalidation_and_ready_responses`, `hook_errors_skip_later_user_hooks_but_submit_generations_with_command_status_and_duration`, `unchanged_display_skips_redraw_but_restores_fallback`.
- WHEN a response's generation differs from the current shell generation, Capsule SHALL leave the prompt unchanged. Spec: `responses_must_match_exact_generation`, `stale_and_future_responses_do_not_replace_prompt`, `rejected_future_completion_does_not_satisfy_pending_generation`, `events_for_other_or_settled_generations_change_nothing`.
- WHEN an accepted response leaves the displayed prompt unchanged, Capsule SHALL skip redraw; a matching result SHALL still replace fallback. Spec: `unchanged_display_skips_redraw_but_restores_fallback`.
- WHEN I/O is partial or backpressured, Capsule SHALL retain framing state and complete the partial frame before replacement, or reset transport. Unterminated EOF frames SHALL be rejected; read credits SHALL resume pending shell writes. Spec: `framing_is_independent_of_chunking_and_cancellation`, `partial_response_returns_before_the_remaining_bytes_arrive`, `reading_bytes_grants_credit_but_eof_does_not`, `backpressure_completes_large_request_without_more_keyboard_input`, `backpressured_frame_completes_before_the_newest_pending_request`.

Keep acquisition states distinct: `Pending` is unfinished, `Ready` contains a value, `Missing` has no matching source data, and `Failed` retains the acquisition error. Allocate fresh observations per generation; never copy retained display into acquisition. Decode OS bytes only at the display boundary. Trim file/command output, preserve environment text, and extract regex capture group 1.

Keep at most one settled display snapshot in the worker; do not retain displays per cwd. Superseding unfinished work may keep showing that snapshot only while cwd, exported environment, and the accepted plan remain unchanged. With no compatible settled display, render only local inputs until completion. The completion bit describes acquisition, not whether the displayed information is retained.

## Resources and shutdown

Bound every frame, snapshot, source value, plan size, concurrency level, and deadline. [limits.rs](../crates/core/src/limits.rs) defines each limit once, and [threat-model.md](threat-model.md#6-current-resource-limits) lists them. Change a constant and its row together; the docs test fails otherwise.

Keep permit ownership with blocking tasks and delayed reapers until they finish. New generations must not accumulate replacement work behind abandoned operations.

Each command owns a process group. Clean up the group and reap the direct child after completion, cancellation, timeout, output overflow, or worker shutdown. Bound pipe cleanup when descendants retain stdout. Commands that deliberately leave the group/session are outside this lifecycle guarantee.

Use rustix for safe OS operations and CLOEXEC shell descriptors. Shell exit/exec closes the transport; worker EOF/signals cancel active work. Preserve these boundaries with the real-platform checks in [testing.md](testing.md).
